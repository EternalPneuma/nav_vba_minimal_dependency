## Destination

形成可直接交给后续实施任务的 `docs/运行.md` 与 `docs/维护.md` 编写规格，明确两份文档的结构、内容边界、截图要求、交叉链接和验收标准。

## Notes

- 领域：产品净值 VBA 报表的运行交接与长期技术维护。
- 本地图只产出文档编写规格，不实际撰写文档、采集截图或修改程序。
- 所有说明以仓库中已经验证的代码、工作簿和流程为准；计划功能不得写成现有能力。
- `运行.md` 面向只具备 Excel 和文件管理基础的运行人员，要求简洁、图文并茂。
- `维护.md` 面向技术维护人员，要求全面并尽量维持纯文本。
- `报表配置与操作手册.md` 收窄为业务配置参考。
- HITL 决策会话使用 grilling 和 domain-modeling；信息架构原型使用 prototype；维护架构分析同时参考 codebase-design。
- 文档使用中文；源码名称、宏名称和命令保持原样。

## Decisions so far

- [核实标准运行流程与停止条件](resolutions/核实标准运行流程与停止条件.md)：运行基线采用“外网准备与转移 → 内网产品业绩展示优先 → 开放日人工确认后完整重跑 → 按需独立运行一页通和推荐材料 → 分交付物人工检查”；面板完成不等于业务验收，异常明细、日期不一致和未授权业务判断均必须停止升级。
- [确定运行手册的信息架构](resolutions/确定运行手册的信息架构.md)：选择任务优先结构，以每周标准流程为正文主干，开放日紧邻主流程，附加交付物按需进入，检查和停止条件集中维护；每步固定使用“你要做什么／正常结果／如果不是这样”，配置与维护细节只摘要并链接。
- [核实系统架构与维护入口](resolutions/核实系统架构与维护入口.md)：维护基线采用“宏工作簿承载业务状态、仓库 VBA 承载程序权威、同级文件与相对资源目录作为交换接口”；维护指南须按修改意图导航，并明确 CP936/Office 约束、三条主调用链、工作簿无自动数据回滚、单项宏日期串用风险及业务备份不属于源码恢复。
- [确定维护指南的信息架构、修改导航与故障边界](resolutions/确定维护指南的信息架构与修改导航.md)：采用 B 增强版“系统分层优先”，从 GitHub Clone/Fork 和完整性边界开始，以架构与模块地图支持维护人员及 LLM 建立完整上下文，同时保留按修改意图索引、业务确认边界、四个变更关卡以及按症状诊断和恢复。

## Not yet specified

- 内外网传输介质、绝对落点、审批与联系人，以及三类交付物的业务截止时间、预期数量和最终签字人，需在后续交接记录与验收规格中明确。
- 12 月一页通 PPT 模板已强制加入 Git 跟踪；`backup` 工作簿仍不跟踪，业务数据备份的保管介质、保留周期、恢复责任人和验收方式尚未定义。
- 当前文档称 `报表配置` 有五张表，但源码和工作簿实际为六张；后续三份文档边界与验收规格需明确修正位置。
- 目标内网的 Office 具体版本、宏策略、PowerPoint COM 可用性、目录权限和 VBA 同步电脑的 CP936 条件仍需现场验收。
- GitHub 原仓库写权限负责人、Pull Request 审批人、分支保护策略，以及内网正式工作簿与 Git 快照的发布／回传方式尚未确定。
- LLM 使用平台、可上传的数据范围、工作簿和错误截图的脱敏要求尚未确定。

## Out of scope

- 实际撰写 `docs/运行.md`、`docs/维护.md` 或重写现有配置手册。
- 在 Excel 中采集、裁剪、脱敏或标注截图。
- 修改 VBA、Python、同步脚本、工作簿、模板或其他程序资源。
- 修复核实过程中发现的缺陷；相关问题应另行登记。
- 代替交接负责人执行最终人工验收。
