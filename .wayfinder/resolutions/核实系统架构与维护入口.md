# 核实系统架构与维护入口

## 结论

维护指南应把本系统描述为“以宏工作簿为运行与业务状态中心、以仓库源码为程序权威、以同级文件和相对资源目录为交换接口”的 Windows Office 自动化系统，而不是 Python 应用，也不是仅靠 Git 源码即可重建的无状态程序。

最重要的维护边界是：

1. `上层产品净值数据库.xlsm` 保存运行数据、业务主数据、配置、开放日台账和已部署 VBA，是内网运行中心。
2. `scripts/vba` 是 VBA 程序的维护权威；不要把 VBE 中的临时修改当成源码。`sync-vba.ps1` 是源码进入工作簿的唯一仓库化部署入口。
3. Python 不调用 VBA，也不参与内网报表计算。`fetch_reits_total_return.py` 只在可联网环境生成一页通输入；`compare_report_workbooks.py` 只做外网开发回归比较。
4. 工作簿同级目录和 `assets` 相对目录构成事实上的文件接口。大量模块通过 `ThisWorkbook.Path` 和严格文件名发现输入、输出和模板，不能只复制工作簿而丢失目录结构。
5. 日常主按钮是面向运行人员的深接口；箭头单项任务、维护工具、VBE 和同步脚本是维护接口。普通恢复应优先修正根因后完整重跑，而不是任意拼接单项宏。

## 一、系统组成和部署关系

### 1. 运行与状态中心

`上层产品净值数据库.xlsm` 同时承担四种职责：

- 保存 181 净值、绘图净值等持续增长的数据；
- 保存产品、开放日、推荐材料关系等业务主数据；
- 保存 `报表配置` 中六张配置表；
- 承载由 `scripts/vba` 同步进入 VBE 的运行代码。

因此它既不是可随时由源码生成的构建产物，也不是源码的唯一权威。程序逻辑以仓库 VBA 文件为准，业务数据和当前配置以经过确认的工作簿为准。维护指南必须分别说明代码恢复和数据恢复，不能用“重新同步 VBA”代替工作簿数据恢复。

当前工作簿只读结构核实到 11 张工作表：

- `上层产品净值数据(181)`
- `绘图净值数据`
- `产品分类`
- `产品信息`
- `产品要素`
- `主要底层资产`
- `底层资产对应关系`
- `开放日`
- `报表配置`
- `配置说明`
- `开放日待确认`

`报表配置` 当前实际有六张表：`tblReportCategories`、`tblReportGroups`、`tblOutputSchemes`、`tblReportCharts`、`tblWeeklyRecommendationProducts`、`tblOnePageVersions`。现有配置手册所写“包含五个独立 Excel 表格”与工作簿及源码不一致，维护文档规格必须按六张处理并要求后续修正文案。

### 2. 仓库程序与资源

- `scripts/vba/data`：配置接口、批处理错误传播、181 导入、开放日确认与计算、分类表现和展示报表。
- `scripts/vba/chart`：绘图净值导入、产品汇总、图表生成、PNG 导出。
- `scripts/vba/product_one_page`：一页通独立预检、数据、图表验证和 PowerPoint 输出。
- `scripts/vba/weekly_recommendation`：推荐材料依赖更新与正式材料生成。
- `scripts/vba/optional_panel`：`AAA启动控制台`、动态 UserForm、按钮调用链和状态显示。
- `scripts/vba/tool`：破坏性数据维护及检查查询宏。
- `scripts/py`：外网数据抓取与开发回归工具。
- `assets/chart_templates`：四个 Excel 图表模板。
- `assets/images`：展示报表和推荐材料固定图片。
- `assets/*.pptx`：一页通版本模板。
- `sync-vba.ps1`：VBA 部署适配器，不是日常数据步骤。

所有 UserForm 控件都在 `UserForm_Initialize` 中动态创建，`.frm` 不依赖人工绘制控件。同步脚本保留内置 Sheet/`ThisWorkbook` 文档模块；默认全量同步会删除其他标准模块和类模块后按仓库文件重建，并原地更新已有 UserForm 代码。因此在 VBE 新建但未进入 `scripts/vba` 的模块，或只在 VBE 修改的代码，下一次全量同步会丢失。

### 3. 文件接口

主工作簿同级目录承担输入和输出交换：

```text
外部输入
├─ HS-181_多账套净值查询_yyyymmdd.xlsx
├─ 净值数据浏览表 yyyy-mm-dd至yyyy-mm-dd.xlsx（可选，绘图净值优先来源）
└─ yyyymmdd-中证REITs全收益.xlsx（一页通）

主工作簿
└─ 上层产品净值数据库.xlsm

相对资源
└─ assets\chart_templates、assets\images、assets\*.pptx

主要输出
├─ yyyyMMdd-上层产品分类表现.xlsx
├─ 产品净值汇总_yyyyMMdd.xlsx
├─ 产品图表_yyyyMMdd\（含 raw\）
├─ yyyyMMdd-产品收益展示.xlsx
├─ yyyyMMdd-产品一页通.xlsx 与各版本 PPT
└─ 推荐材料-yyyyMMdd.xlsx
```

绝大多数路径由 `ThisWorkbook.Path` 拼接。配置中的 PPT 模板只允许工作簿目录下的安全相对路径，不允许绝对路径或 `..`。

## 二、内外网数据流和模块边界

```text
外网：akshare / 中证指数数据
  └─ fetch_reits_total_return.py
       └─ yyyymmdd-中证REITs全收益.xlsx ─────┐
                                             │ 转移
外网开发：scripts/vba + sync-vba.ps1          │
  └─ 已同步的上层产品净值数据库.xlsm ─────────┤
                                             ▼
内网：181 查询文件 ──> 主工作簿 ──> Excel/PPT/PNG 交付物
                         │
                         └─ VBA 通过 Office COM 调用 PowerPoint（一页通）
```

应明确以下边界：

- `fetch_reits_total_return.py` 依赖外网、`pandas`、`akshare`、`openpyxl`，默认输出到仓库根目录；VBA 只消费生成的 xlsx，不启动 Python。
- `compare_report_workbooks.py` 依赖 `openpyxl`，只比较工作表顺序、尺寸、合并区域和单元格值；它不验证格式、图片、图表、VBA 或 PPT，不能作为完整回归验收。
- 内网 VBA 运行本身不依赖 Python；一页通依赖已转移的 REITs xlsx 和本机 PowerPoint。
- 仓库没有规定传输介质、审批、绝对落点和联系人，这些仍属于交接记录，不得写成架构事实。

## 三、权威工作表和写入责任

| 工作表 | 权威内容 | 主要写入者／维护入口 | 不应误解为 |
|---|---|---|---|
| `上层产品净值数据(181)` | 已导入的 181 当前净值和资产净值；驱动主流程基准日期 | `Data01_ImportNav181` 从严格命名的 181 文件增量写入 | 仓库源码可重建的数据 |
| `绘图净值数据` | 长期图表历史及图表计算输入 | `Chart01_ImportNavData`；有浏览表时优先导入浏览表，否则从 181 补配置所需产品 | 产品范围配置 |
| `产品分类` | 是否导出、唯一归属、系列、理论间隔、基准收益率等产品业务维护项 | 业务配置维护；`Data02` 会重算基准日期、开放日和对应净值等派生列 | 只读输出表 |
| `产品信息` | 信托计划代码、产品简称、成立日等身份信息 | 业务配置维护 | 可由名称或首个净值日推断的信息 |
| `开放日` | 已确认开放日台账 | 业务人工维护；确认提议后由开放日模块追加 | 自动推算结果 |
| `开放日待确认` | 提议、确认状态和流程协调状态 | `OpenDate_*` 创建和处理，人工只审核状态 | 权威开放日台账 |
| `报表配置` | 分类、分组、字段方案、图表位置、推荐材料范围、一页通版本 | 六张命名表；配置预检是统一读取接口 | VBA 公式或任意布局区 |
| `产品要素` | 推荐材料的产品属性和产品规模承载区 | 属性人工维护；`Weekly01_UpdateDependencies` 用最新 181 资产净值更新规模 | 推荐材料产品范围；范围以 `tblWeeklyRecommendationProducts` 为准 |
| `主要底层资产` | 推荐材料资产层级、节点和排序 | 关系人工维护；依赖更新会重写可计算的节点说明 | 产品规模原始来源 |
| `底层资产对应关系` | 底层节点到产品规模的汇总映射 | 业务／技术维护 | 展示结果 |
| `配置说明` | 配置说明、验证列表和部分最后运行信息 | 迁移／输出模块 | 业务主数据 |

同名信息存在于多个输出文件时，仍以上表所列工作表或命名配置表为维护入口，不应直接修正式输出文件。

`ReportConfig_*` 是多个流水线共享的配置接口；一页通在其上增加 `OnePage_*` 独立预检。维护时应优先从这些共享接口定位配置问题，避免在各输出模块复制读取规则。

## 五、环境和发布约束

### 日常运行

- Windows 桌面版 Excel，当前文档口径为 Excel 2007/VBA；必须允许打开和运行宏。
- 工作簿必须先保存，输入、资源和输出目录必须可读写。
- VBA 使用 MSForms、`Scripting.Dictionary` 和 `VBScript.RegExp`；操作面板依赖 `frmOperationPanel` 与 `clsOperationPanelButton` 已正确同步。
- 一页通需安装可由 COM 启动的 PowerPoint；普通展示报表和推荐材料不调用 PowerPoint。
- 正式输出文件被占用时替换可能失败，应关闭输出文件后再运行。

### VBA 开发与同步

- `.bas`、`.cls`、`.frm` 必须是严格 UTF-8、CRLF，且全部字符可无损编码为 CP936。
- `sync-vba.ps1` 必须保持 UTF-8 BOM；当前核实 BOM 存在。
- 同步只允许在 Windows ANSI code page CP936 上运行；脚本通过 Win32 `GetACP` 强制阻止其他环境。
- 需要 Windows PowerShell 5.1 或 PowerShell 7、Excel COM、宏工作簿写权限，并在 Excel 信任中心启用“信任对 VBA 工程对象模型的访问”。
- 同步前预检源码，导入后从 VBE 读回比较；任一模块失败时不保存工作簿。测试同步必须使用临时工作簿副本。
- 本次只做静态与只读核实，没有在当前环境绕过 CP936 保护执行同步，也没有在目标内网机实际运行 Office 流程。

### Python 外网工具

- `fetch_reits_total_return.py` 需要 Python、外网和 `pandas akshare openpyxl`。
- `--end-date` 使用 `yyyymmdd`，不得早于 `20250717`。
- Python 脚本通过语法编译检查；未在本次核实中联网请求 akshare。

## 七、恢复路径和已知限制

1. **没有发现工作簿数据事务或自动业务备份。** 181 导入、绘图净值导入、开放日确认、推荐材料依赖更新和维护工具会直接改主工作簿。出错后如果保存，不能依靠 VBA 自动回滚；高风险维护前必须制作可识别日期和目的的工作簿副本。
2. **同步失败保护只覆盖代码部署。** `sync-vba.ps1` 只有全部导入和读回成功才保存，但它不替代修改前的工作簿副本，也不恢复业务数据。
3. **输出替换保护不完全一致。** 分类表现、展示报表和一页通使用临时文件／备份后替换；产品汇总和推荐材料存在直接覆盖路径。维护指南不能笼统承诺所有输出失败都会保留旧文件。
4. **若干单项宏选择目录中“最新”的匹配文件。** `Chart03`、`Chart04` 等会寻找最新 `产品净值汇总_yyyymmdd.xlsx`，一页通图表步骤寻找最新临时文件。目录中混有未来日期或错误日期文件时，单项补跑有日期串用风险；完整流程和逐项日期核对是默认恢复路径。
5. **浏览表会改变绘图净值来源。** 同级目录只要存在严格匹配的 `净值数据浏览表 ...xlsx`，`Chart01` 就优先处理浏览表；完全没有时才回退到内部 181。维护排查必须记录目录中实际存在的所有匹配文件。
6. **回归脚本覆盖面有限。** `compare_report_workbooks.py` 不检查样式、图片、图表和 PPT；视觉产物必须保留人工或 Office 自动化验证。
7. **静态运行资源与业务备份采用不同保管方式。** 核实后已将 `assets/产品一页通-交鑫致远-模板-12月.pptx` 强制加入 Git 跟踪；它虽然仍匹配 `.gitignore` 的 `*.pptx` 规则，但已跟踪文件后续修改仍可正常纳入版本控制。发布检查必须确认两份一页通模板都在 Git 清单和运行包中。`backup` 下的工作簿副本仍不跟踪，业务数据备份与灾备渠道需另行定义。
8. **当前主工作簿有未提交修改。** 维护与发布时必须先辨认正式业务状态、开发副本和 Git 版本，避免用源码同步或 Git 恢复覆盖较新的内网业务数据。

建议的恢复层级是：

```text
输出异常且上游状态有效
→ 先解除占用并核对同日输入／中间文件
→ 维护人员确认依赖后补跑单项

主流程或业务数据异常
→ 保留现场副本和错误证据
→ 从修改前工作簿副本恢复
→ 修正输入／配置／代码
→ 完整重跑并逐交付物验收

代码部署异常
→ 不保存测试副本
→ 修复 scripts/vba 或同步环境
→ 对新的临时工作簿副本重新全量同步和读回验证
→ 验证通过后才更新正式工作簿
```

## 八、维护指南必须采用的架构基线

后续 `docs/维护.md` 的规格至少应要求：

- 首页明确“仓库源码权威／工作簿业务状态权威／配置工作表权威”的三类权威，不使用含混的“数据库即源码”。
